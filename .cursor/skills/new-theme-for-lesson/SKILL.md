# New theme for lesson

Подбирает **ровно 5 тем** на выбор для нового открытого урока. Файлы урока не создаёт: после выбора темы пользователь запускает скилл `new-lesson`.

Канон репозитория - корневой `AGENTS.md`.

## Что нужно до предложений

Нужна **программа** (`MLOps`, `DE`, `AgentOps`, ...). Если программы нет - спроси. Не подгоняй неизвестный курс под соседний префикс.

Практика на вебинаре всегда либо **Yandex Cloud**, либо **локальная Ollama**. Если пользователь ещё не сказал, где показывать занятие - спроси до или сразу после списка тем. Не выбирай бэкенд сам и не закладывай AWS / GCP / Azure / чужой API модели в карточки.

Месяц группы (`YYYY-MM`) не обязателен: этот скилл только про темы. Если месяц уже назван и папка `courses/{Program}/{Program}-{YYYY-MM}/` существует - всё равно предложи темы, но явно скажи, что урок уже есть, и не перезаписывай его.

Не пиши README / `presentation.md` / `practice.md` / код. Не коммить.

## Порядок действий

1. Найди папку `courses/{Program}/`. Если её нет - всё равно предложи темы (программа может быть новой), но сначала собери программу курса из внешних источников (шаг 2).
2. Собери **программу курса**, не только прошлые вебинары:
   - `courses/{Program}/README.md` и любые файлы программы, которые приложил пользователь (PDF, ссылка, список модулей).
   - Если в репозитории программы нет - поищи публичную программу OTUS по названию курса (сайт OTUS, лендинг программы). Кратко перескажи 5-10 опорных модулей/навыков, на которые опираешься. Если найти нельзя - опирайся на прошлые уроки и типичный состав курса, и **явно пометь**, что программа восстановлена по косвенным данным.
3. Прочитай прошлые открытые уроки этой программы: у каждого `README.md` и, если есть, заголовки слайдов в `presentation.md`. Список тем запиши себе как **запрет на дубли**. Соседние программы не копируй как «уже было», если инструмент тот же, но роль и практика другие (например Prefect у DE vs оркестрация у MLOps - всё равно проверь, не повторяешь ли ты тот же сценарий один в один).
4. Предложи **ровно 5** тем. Каждая тема - **один инструмент или один небольшой навык**, который укладывается в формат открытого урока:
   - теория: **4-6 слайдов** (`Теория 1` ... `Теория N`);
   - практика: **около 40 минут**, живые шаги, которые можно показать на вебинаре.
5. После списка спроси, какую тему брать в `new-lesson` и, если ещё не ясно, **Yandex Cloud или Ollama**. Пока пользователь не выбрал тему - файлы не создавай.

## Критерии хорошей темы

Тема проходит, если одновременно верно:

- Есть **один якорь**: конкретный инструмент (`Langfuse`, `Prefect`, `pre-commit`, `Ruff`) или узкий навык (`structured outputs`, `один тип DAG в оркестраторе`). Не «введение в MLOps», не «обзор LLM», не «как менеджеру внедрить ИИ».
- Якорь **есть в программе курса** или является практическим входом в один её модуль. Не тащи модный инструмент, которого нет в курсе, без явной связи («это лаборатория к модулю X»).
- Тема **не повторяет** прошлый открытый урок той же программы (даже другими словами).
- Практику реально провести за ~40 минут: установка/запуск, 2-4 осмысленных шага, видимый результат. Стек: выбранный бэкенд (**Yandex Cloud** или **Ollama**), Python **3.12.8**, запуск через **uv**, без `.venv` как шага занятия.
- Теории хватает на 4-6 слайдов тезисов, не на мини-курс: зачем инструмент, модель понятий, как встроить, типичные ошибки, как проверить результат.

Отсекай:

- обзоры «пять инструментов за вебинар»;
- темы, где практика = только слайды или «дальше сами»;
- полный цикл продукта / архитектура платформы / сравнение облаков;
- дубли соседнего урока с заменой названия инструмента.

Ориентиры зерна (уже существующие уроки): Langfuse и трассы агента; Prefect и один flow; Black/Ruff + pre-commit; Argo Workflows в ML-пайплайне. Контрпример слишком широкого: «от идеи до внедрения ИИ-продукта».

## Формат ответа

Язык - русский. Только ASCII-дефис `-`, без длинного и среднего тире.

Сначала блок **Контекст** (коротко):

- программа;
- откуда взята программа курса (репозиторий / сайт OTUS / пользователь / восстановлено);
- уже закрытые темы прошлых открытых уроков (список названий);
- бэкенд практики, если пользователь уже назвал (Yandex Cloud / Ollama), иначе пометка «ещё не выбран».

Затем ровно пять карточек. Нумерация 1-5. Шаблон карточки:

```markdown
### {N}. {конкретное название темы}

- **Якорь:** {один инструмент или навык}
- **Зачем в этом курсе:** {1 предложение: какой модуль/боль закрывает}
- **Почему не повтор:** {чем отличается от уже проведённых уроков}
- **Теория (4-6 слайдов):**
  1. ...
  2. ...
  3. ...
  4. ...
  (5-6 по необходимости)
- **Практика (~40 мин):** {3-5 шагов, что участник увидит в конце}
- **Риск по времени:** {низкий / средний; что может раздуть практику}
```

Названия - как для лендинга: конкретные, без лозунгов. Можно начинать с `Тема: ...`, как в README уроков.

В конце: одна строка «какую тему готовим в `new-lesson`?» и, если бэкенд не назван, вопрос «Yandex Cloud или локальная Ollama?». Не рекомендуй больше одной «любимой», если пользователь не просил ранжировать. Если просил - пометь одну как приоритет и почему (программа + новизна + укладка в 40 минут).

## Примеры зерна

Хорошо: «Langfuse: трасса и оценка одного агента»; «pre-commit: Ruff не пускает плохой код в git»; «Prefect: первый scheduled flow для ETL».

Плохо: «современный MLOps»; «агенты и RAG с нуля»; «как выбрать оркестратор»; «Yandex Cloud для всего курса».

# AGENTS.md

Инструкции для агентов, работающих с репозиторием открытых уроков OTUS.

## Обзор

Репозиторий - набор материалов открытых уроков (вебинаров) OTUS. Программы не фиксированы: спикера регулярно зовут на новые курсы, поэтому в `courses/` появляются новые папки. Пример новой программы - `AgentOps`.

Это не единое приложение. Каждый урок - отдельная папка внутри `courses/`. Общего `package.json`, CI или тестового раннера нет.

Корневой `README.md` - короткое человеческое описание проекта. Детали урока живут в `README.md` внутри папки урока.

## Стек по умолчанию

- Облако всегда **Yandex Cloud**. Не подставляй AWS, GCP или Azure, если пользователь явно не попросил другой провайдер. Типичные сервисы: Object Storage (S3-совместимый API), Cloud Functions, Terraform, VPC, IAM.
- Python-зависимости и запуск всегда через **uv**. Единственный манифест окружения - **`pyproject.toml`**. Версия Python сейчас строго **`==3.12.8`** (`requires-python = "==3.12.8"`). Не используй pip, poetry или conda, если пользователь явно не попросил.
- **Никогда не создавай `.venv`**: не запускай `uv venv`, `python -m venv`, `virtualenv`. Не активируй окружение. Команды - `uv add`, `uv run`, при необходимости `uv sync`. Если `uv` сам положит `.venv` на диск, не документируй это как шаг и не коммить.
- Презентации всегда готовятся **текстом в Markdown**. В каждом уроке в git обязательно: `{lesson}/presentation.md` (слайды) и `{lesson}/practice.md` (полный ход практики). Не создавай `.pptx`, Google Slides, PDF или HTML-слайды, если пользователь явно не попросил другой формат.
- Никогда не используй длинное тире (em dash, U+2014) и среднее тире (en dash, U+2013). Только ASCII-дефис `-`. Это касается README, слайдов, `practice.md`, комментариев и строк в коде.

## Структура

```
courses/{Program}/{Program}-{YYYY-MM}/
  README.md              # публичное описание урока (в git)
  presentation.md        # слайды, только Markdown (в git)
  practice.md            # полный ход практики (в git)
  artifacts/             # код и прочие локальные артефакты, gitignored
    code/                # скрипты и команды к практике
```

Папки программ в `courses/` - открытый список. Уже есть, например:

- `MLOps` - MLOps
- `DE` - Data Engineering
- `ML-Basic` - ML Basic
- `ML-Special` - ML Special
- `LLM-DD` - LLM / Deep Dive
- `AI-ML-PM` - продукт / менеджмент ИИ

Если пользователь назвал курс, которого ещё нет в `courses/` (например `AgentOps`), создай новую папку программы. Не подгоняй новый курс под существующий префикс. Имя папки - короткое, латиницей, в том же стиле, что у соседей (`AgentOps`, не `agent-ops` и не `Agent Ops`).

Имя папки урока совпадает с группой: `{Program}-{YYYY-MM}`. Примеры: `courses/MLOps/MLOps-2026-03`, `courses/DE/DE-2026-02`, `courses/AgentOps/AgentOps-2026-10`.

Не переименовывай существующие папки и не смешивай материалы разных уроков.

## Что трогать, а что нет

- Меняй только запрошенный урок, если явно не сказано иначе.
- Не копируй `courses/LLM-DD/LLM-DD-2026-09/README.md` как шаблон: в файле прямо указано, что его нельзя использовать как шаблон.
- Не коммить `artifacts/`, `.env` и секреты. Они в `.gitignore`. `.venv` тоже в ignore - на случай если `uv` создал его сам; агент его всё равно не создаёт.
- Не коммить ключи облаков, токены и содержимое `.env` из `artifacts/code/`.

## Новый урок

Сценарий создания - скилл `.cursor/skills/new-lesson/SKILL.md`.

1. Создай папку `courses/{Program}/{Program}-{YYYY-MM}/`.
2. Добавь `README.md` с описанием для лендинга/анонса.
3. Всегда добавь `{lesson}/presentation.md` и `{lesson}/practice.md` - только Markdown, оба в git.
4. Практический код клади в `{lesson}/artifacts/code/`. Зависимости ставь через `uv`. План на слайде «Практика» и шаги в `practice.md` должны совпадать с этим кодом.

Коммит: `feat({Program}): {Program}-{YYYY-MM} open lesson` (или уточнение темы, если папка уже существует).

## README урока

Язык: русский.

Типичная структура существующих уроков:

```markdown
# Тема: {название}

{1-3 предложения: боль аудитории и обещание урока}

## Что вас ждет на вебинаре?

1. ...
2. ...
3. ...

## Кому будет полезно?

- {роль}: {зачем}
- ...

## Что вы узнаете по итогам вебинара?

- Как ...
- Как ...
- Как ...
```

Правила:

- Тема конкретная, без общих лозунгов вроде «введение в ML».
- 3 пункта «что будет», 3 аудитории, 3 исхода. Можно чуть больше, если урок того требует.
- Исходы формулируй как умения: «как настроить…», «как запустить…», не как абстрактные «узнаете про…».
- Не обещай полный курс, сертификат или домашние задания - это открытый урок на ~50-90 минут.
- Тон: практический, прямой, без канцелярита и воды.
- Эмодзи в заголовках секций допустимы, если соседние уроки той же программы их используют. Не навязывай эмодзи в уроки, где их нет.

Ориентиры по стилю: `courses/MLOps/MLOps-2026-03/README.md`, `courses/DE/DE-2026-02/README.md`, `courses/ML-Basic/ML-Basic-2026-01/README.md`.

## Слайды и практика

В каждом уроке всегда два Markdown-файла **в корне урока** (они в git, не в `artifacts/`):

- `{lesson}/presentation.md` - слайды для показа
- `{lesson}/practice.md` - полный ход практики, все действия и команды

Не генерируй `.pptx` / `.key` / PDF «для показа», пока об этом не попросили отдельно. Не дублируй маркетинговый README один в один.

### presentation.md

Жёсткий порядок слайдов:

1. **Цели** - ровно три коротких ответа на вопрос «что вы сможете сделать после занятия». Умения, не темы. Максимально коротко.
2. **Смысл занятия** - ровно один смысл: ответ на вопрос «для чего нам это уметь?».
3. **Теория** - 4-6 слайдов, заголовки вида `Теория 1`, `Теория 2`, … Не больше шести.
4. **Практика** - один слайд: план практики. Пункты плана совпадают с шагами в `practice.md` и с тем, что лежит в `artifacts/code/`.

Старый конспект `courses/AI-ML-PM/AI-ML-PM-2026-10/presentation.md` не использовать как шаблон этого формата.

### practice.md

Полный сценарий занятия по практике: каждый шаг, каждая команда, что должно получиться. Можно провести урок, читая только этот файл. Не оставляй «дальше сами». Команды и пути должны совпадать с `artifacts/code/` и со слайдом «Практика».

## Код в artifacts/code/

`artifacts/code/` - песочница к уроку: скрипты, `pyproject.toml`, ноутбуки. Лежит внутри `artifacts/`, в git не попадает.

- Python строго **3.12.8**: в `pyproject.toml` поле `requires-python = "==3.12.8"`. Не пиши `>=3.12`, не создавай `.python-version`, если хватает `pyproject.toml`.
- Не создавай `.venv`. Зависимости и запуск только через `uv add` / `uv run`. Не оставляй `requirements.txt` как основной способ установки.
- Предпочитай небольшие скрипты и явные шаги, которые можно показать на вебинаре.
- Секреты только в `.env`, не в коде. Не печатай ключи в логи.
- Инфраструктура и демо - в Yandex Cloud. Для Object Storage используй endpoint `https://storage.yandexcloud.net`, не AWS.

Стиль Python:

- Все `import` только в начале файла. Не импортируй внутри функций и классов.
- Константы и модульные переменные - сразу после импортов, до функций.
- Первый оператор файла - module docstring:

```python
"""Module: {имя модуля}
Description: {коротко, но емко, зачем файл}.
"""
```

- У каждой функции и метода: type hints на аргументах и возврате, плюс docstring.

Корневого линтера и тестов нет. Если в `artifacts/code/` есть `pyproject.toml`, проверяй код из этой папки (`uv run`; ruff/black - только если они уже в зависимостях урока).

Минимальный `pyproject.toml`:

```toml
[project]
name = "{lesson-slug}"
version = "0.1.0"
requires-python = "==3.12.8"
dependencies = []
```

## Коммиты и PR

Сообщения на английском, Conventional Commits:

- `feat({Program}): {Program}-{YYYY-MM} open lesson`
- `feat(docs): ...`
- `fix(docs): ...`
- `fix(markdown): ...`

Не коммить, пока пользователь явно не попросил. Не пушить без явной просьбы.

Отвечай пользователю по-русски. Учебные тексты (`README.md`, `presentation.md`, `practice.md`, комментарии в демо-коде) тоже на русском, если не попросили иначе.

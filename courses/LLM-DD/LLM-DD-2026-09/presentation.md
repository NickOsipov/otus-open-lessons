# Structured Outputs: как заставить LLM возвращать нужную структуру

## Цели

После занятия вы сможете:

1. Описать контракт ответа JSON Schema
2. Запросить структурированный ответ у LLM
3. Проверить ответ перед передачей в систему

## Смысл занятия

Превращать вероятностный ответ LLM в надежный контракт между моделью и прикладным кодом.

## Теория 1. Почему промпта недостаточно

- LLM генерирует последовательность токенов, а не объект Python
- Просьба "верни JSON" не гарантирует нужные поля и типы
- Валидный JSON может нарушать бизнес-контракт
- Ошибка проявляется уже в базе данных, API или пользовательском интерфейсе

Три разных уровня качества:

1. Текст похож на JSON
2. Синтаксически валидный JSON
3. JSON соответствует схеме и бизнес-ограничениям

## Теория 2. JSON Schema как контракт

Схема задает:

- тип корневого значения
- обязательные поля
- допустимые типы и перечисления
- вложенность и массивы
- запрет неизвестных полей через `additionalProperties: false`

Один контракт можно использовать для генерации, проверки, тестов и документации API.

## Теория 3. Три способа получить структуру

Yandex AI Studio совместим с OpenAI API, поэтому все три режима задаются параметром `response_format` официального OpenAI SDK.

### Инструкция в промпте

`response_format` не передается. Просто, но формат не гарантирован.

### JSON Object

`{"type": "json_object"}` гарантирует валидный JSON, но не состав и смысл полей.

### JSON Schema

`{"type": "json_schema", ...}` ограничивает генерацию схемой на стороне модели. Это и есть Structured Outputs в строгом смысле.

## Теория 4. Схема из модели Pydantic

- Pydantic описывает контракт рядом с кодом
- `model_json_schema()` создает JSON Schema для LLM
- `model_validate_json()` повторно проверяет границу системы
- `Enum`, `Literal` и ограничения полей уменьшают неоднозначность
- `extra="forbid"` не пропускает неожиданные поля

Проверка нужна даже при schema-constrained generation: остаются сетевые ошибки, смена модели, несовместимость схемы и бизнес-правила.

## Теория 5. Надежный производственный контур

1. Версионировать схему вместе с кодом
2. Разделять ошибки транспорта, JSON и валидации
3. Ограничивать повторы и применять backoff
4. Сохранять метрики отказов без секретов и персональных данных
5. Иметь явный fallback: повтор, ручная проверка или отказ операции

Structured Outputs снижает класс ошибок формата, но не гарантирует фактическую правильность ответа.

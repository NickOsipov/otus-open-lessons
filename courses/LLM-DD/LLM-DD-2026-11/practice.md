# Практика: поиск в Qdrant с фильтром по метаданным

За 40 минут поднимем Qdrant локально, загрузим базу знаний вымышленного интернет-магазина «Орбита», сравним обычный векторный поиск с поиском по метаданным и отдадим найденный контекст в локальную модель `llama3.2:3b` через Ollama. План совпадает со слайдом «Практика» в `presentation.md`.

Все команды Python выполняются из `courses/LLM-DD/LLM-DD-2026-11/code/`.

## Что понадобится

- установленный `uv`
- Python 3.12.8, который `uv` может установить автоматически
- Docker (чтобы запустить Qdrant)
- установленный [Ollama](https://ollama.com/) со скачанной моделью `llama3.2:3b`
- свободные порты `6333`, `6334` и `11434`

Облачный ключ Yandex Cloud для этой практики не нужен. Ollama отдает OpenAI-совместимый API, поэтому в коде используется пакет `openai`, а не сырые HTTP-запросы.

Первый запуск `fastembed` скачает модель эмбеддингов `intfloat/multilingual-e5-small` (порядка 100 МБ). Спикеру лучше до вебинара прогнать шаг 2 и один раз выполнить:

```bash
ollama pull llama3.2:3b
```

## 1. Поднять Qdrant и создать коллекцию

Время: 7 минут.

Перейдите в папку демо и поднимите Qdrant:

```bash
cd courses/LLM-DD/LLM-DD-2026-11/code
docker compose up -d
```

Проверьте, что контейнер запущен:

```bash
docker compose ps
```

Ожидаемо: сервис `qdrant` в состоянии `running` или `healthy`.

Откройте в браузере дашборд: `http://localhost:6333/dashboard`. Пока коллекций может не быть.

Убедитесь, что Ollama отвечает и модель на месте:

```bash
ollama list
```

Ожидаемо: в списке есть `llama3.2:3b`. Если нет, выполните `ollama pull llama3.2:3b`.

Установите зависимости из `pyproject.toml` и скопируйте настройки:

```bash
uv sync
cp .env.example .env
```

В `.env` уже указаны локальные URL. `OLLAMA_API_KEY=ollama` - заглушка: официальный OpenAI SDK требует непустое поле `api_key`, Ollama ключ не проверяет.

```dotenv
QDRANT_URL=http://localhost:6333
OLLAMA_BASE_URL=http://localhost:11434/v1
OLLAMA_API_KEY=ollama
OLLAMA_MODEL=llama3.2:3b
```

Откройте `config.py`. Обратите внимание на имя коллекции `orbit_knowledge`, размер вектора `384` и метрику `COSINE`. Это контракт коллекции: все точки и все запросы должны использовать одну и ту же модель эмбеддингов.

Создайте пустую коллекцию и индексы payload:

```bash
uv run python 01_create_collection.py
```

Ожидаемо: в терминале появится сообщение, что коллекция `orbit_knowledge` создана, а для полей `department`, `doc_type` и `year` построены индексы. В дашборде Qdrant коллекция станет видна, точек пока 0.

Индексы создаем до загрузки данных: так фильтр сразу опирается на индекс, а не на полный перебор payload.

## 2. Загрузить небольшую коллекцию документов

Время: 7 минут.

Откройте `documents.py`. В корпусе 6 коротких документов:

- актуальные правила возврата товара за 2025 год (`shop` / `returns`)
- устаревшие правила возврата за 2023 год (`shop` / `returns`)
- HR-инструкция про возврат дней отпуска (`hr` / `leave`)
- сроки доставки (`shop` / `delivery`)
- гарантийный ремонт (`shop` / `warranty`)
- политика удаленной работы (`hr` / `policy`)

У каждого документа в payload есть `department`, `doc_type`, `year`, `title` и `text`. Поля `department` и `doc_type` - точные строки, `year` - целое число. Так фильтр не путает `"2025"` и `2025`.

Загрузите точки в Qdrant. Скрипт кодирует тексты моделью `intfloat/multilingual-e5-small` и отправляет векторы вместе с payload:

```bash
uv run python 02_upsert_documents.py
```

Ожидаемо: в терминале `upserted 6 points`. В дашборде у коллекции `orbit_knowledge` число точек станет 6. Откройте любую точку и покажите слушателям payload: вектор сам по себе не содержит отдел и год.

Если загрузка зависла на первом запуске, подождите скачивание ONNX-модели. Повторный запуск берет модель из кэша.

## 3. Выполнить обычный поиск

Время: 5 минут.

Запрос клиента магазина: «как оформить возврат». Без фильтра это только ближайшие векторы.

```bash
uv run python 03_plain_search.py
```

Ожидаемо: в топе окажется HR-документ «Возврат неотгулянного отпуска» или устаревшие правила 2023 года рядом с актуальными. Score у них может быть высоким, потому что в тексте много слов «возврат» и «оформить».

Разберите результат вслух: для RAG это похожий контекст, но не тот процесс. Модель на следующем шаге могла бы начать отвечать про отпуск вместо товара.

## 4. Добавить фильтры по метаданным

Время: 6 минут.

Откройте `filters.py`. Фильтр для витрины магазина:

- `department` равно `shop`
- `doc_type` равно `returns`
- `year` не меньше `2025`

Это `must` из двух `MatchValue` и одного `Range`. HR и доставка отсекаются еще до ранжирования по смыслу.

Запустите поиск с тем же текстом запроса и этим фильтром:

```bash
uv run python 04_filtered_search.py
```

Ожидаемо: в выдаче останется документ «Правила возврата товара 2025». Правила 2023 года, отпуск и гарантия не проходят фильтр.

Покажите в коде, что запрос кодируется той же функцией `embed_query`, что и на шаге 3. Меняется только `query_filter`.

## 5. Сравнить выдачу запросов

Время: 5 минут.

Запустите рядом оба режима:

```bash
uv run python 05_compare.py
```

Ожидаемо: скрипт напечатает две таблицы для одного запроса. Слева топ без фильтра, справа топ с фильтром `shop + returns + year >= 2025`. Слева в выдаче есть чужой отдел или старый год, справа - только актуальная политика возврата.

Коротко зафиксируйте:

- векторный поиск отвечает на вопрос «что похоже»
- фильтр payload отвечает на вопрос «что вообще можно показывать»
- LLM на следующем шаге увидит только то, что вернул Qdrant

## 6. Собрать ответ LLM из найденного контекста

Время: 10 минут.

Откройте `ollama_client.py`. Подключение к Ollama - это тот же OpenAI SDK, что и для облачных моделей. Меняется `base_url`:

```python
OpenAI(
    api_key="ollama",
    base_url="http://localhost:11434/v1",
)
```

Имя модели в `chat.completions.create` - `llama3.2:3b`. Промпт запрещает отвечать вне переданного контекста.

Запустите сравнение двух полных контуров RAG:

```bash
uv run python 06_answer_with_llm.py
```

Ожидаемо: скрипт дважды спросит Ollama. Без фильтра модель с большой вероятностью начнет объяснять возврат дней отпуска или смешает его с товаром. С фильтром `shop + returns + year >= 2025` ответ должен опираться на правила 2025 года: 14 дней, личный кабинет, возврат на карту.

Если запрос к Ollama падает с `Connection error`, проверьте `ollama serve` и URL в `.env`. Если ошибка `model not found`, выполните `ollama pull llama3.2:3b`.

Вывод занятия:

- фильтр не украшение поиска, а граница контекста для модели
- маленькая локальная LLM честно следует плохому контексту
- чинить нужно retrieval, а не просить модель «догадаться», какой документ правильный

Если останется время, уберите в `filters.py` условие по `year` и снова запустите шаг 6: в контекст вернется инструкция 2023 года, и ответ модели про срок возврата может смениться с 14 дней на 7.

По окончании остановите контейнер:

```bash
docker compose down
```

Данные Qdrant в этом демо живут в Docker-томе. Для чистого повтора с нуля удалите том: `docker compose down -v`. Ollama после занятия можно не останавливать.

# Практика: PyMuPDF, страницы PDF в текст для базы знаний

Соберем учебный PDF вымышленного онлайн магазина, осмотрим его через PyMuPDF, извлечем текст по страницам, уберем колонтитулы, сохраним страницы в JSONL и зададим модели вопрос по найденной странице. План совпадает со слайдом «Практика» в `presentation.md`.

Все команды выполняются из `courses/LLM-DD/LLM-DD-2027-01/code/`. Код разложен так: настройки в `config/variables.py`, предметная логика в `src/lib/`, шаги практики в `src/main/`, мелкие помощники в `src/utils/`. Скрипты запускаются с `PYTHONPATH=.`, чтобы импорты `config` и `src` находились от корня `code/`.

## Что понадобится

- установленный `uv`
- Python 3.12.8, который `uv` может установить автоматически
- ключ OpenAI API (`OPENAI_API_KEY`) с доступом к модели `gpt-4o-mini` или другой chat-модели
- доступ в интернет до `api.openai.com` (нужен только на шаге 6)

Бэкенд практики - облачный OpenAI API. Модель вызывается через официальный SDK `openai`, без ручных HTTP-запросов. Шаги 1-5 работают офлайн и без ключа: PyMuPDF разбирает PDF локально.

Спикеру до вебинара: один раз выполнить `uv sync` (скачает PyMuPDF и `openai`) и проверить ключ на шаге 6.

## 1. Собрать учебный PDF и настроить окружение

Время: 6 минут.

Перейдите в папку демо, установите зависимости и скопируйте настройки:

```bash
cd courses/LLM-DD/LLM-DD-2027-01/code
uv sync
cp .env.example .env
```

Впишите в `.env` свой ключ. Модель можно поменять, не трогая код:

```dotenv
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini
```

Ключ живет только в `.env`, файл не попадает в git. Не показывайте его на экране при демонстрации.

Соберите учебный PDF:

```bash
PYTHONPATH=. uv run python src/main/01_make_pdf.py
```

Ожидаемо: `saved orbita_manual.pdf: 5 pages`. Файл появится в `data/orbita_manual.pdf`.

Откройте PDF в любом просмотрщике и покажите слушателям:

- страницы 1-4: доставка, возврат, гарантия, уход за устройством
- сверху на каждой странице серый колонтитул «Орбита - руководство покупателя»
- снизу подвал «Страница N из 5 - редакция 2026»
- страница 5 «Акт приема устройства» выглядит так же, но это картинка: текст на ней не выделяется мышью

Коротко объясните, как сделан скан в `src/main/01_make_pdf.py`: страница рисуется отдельно, превращается в картинку через `get_pixmap`, и в итоговый PDF вставляется только картинка. Так выглядит любой отсканированный договор или акт.

## 2. Осмотреть PDF: страницы, текстовый слой, сканы

Время: 6 минут.

```bash
PYTHONPATH=. uv run python src/main/02_inspect_pdf.py
```

Ожидаемо: заголовок документа, 5 страниц и таблица:

- у страниц 1-4 размер `595x842`, сотни символов текста, `0` картинок и вердикт `текст`
- у страницы 5 `0` символов, `1` картинка и вердикт `скан, нужен OCR`

Разберите в коде:

- `pymupdf.open(PDF_PATH)` - объект `Document`
- перебор `for page in doc` - объекты `Page`
- `page.get_text("text")` - текстовый слой страницы
- `page.get_images()` - картинки на странице

Вывод: проверка текстового слоя - первый шаг любого PDF-пайплайна. Без нее скан попадет в базу знаний как пустая запись, и ошибка останется незамеченной.

## 3. Извлечь текст и блоки одной страницы

Время: 8 минут.

Возьмем страницу 3 «Гарантия и ремонт»:

```bash
PYTHONPATH=. uv run python src/main/03_page_text.py 3
```

Ожидаемо: два блока вывода.

В первом, `get_text('text')`, сплошной текст страницы. Обратите внимание: колонтитул «Орбита - руководство покупателя» и подвал «Страница 3 из 5 - редакция 2026» стоят в одном потоке с полезным текстом. Если передать этот текст в чанкинг, служебные строки попадут в каждый чанк.

Во втором, `get_text('blocks', sort=True)`, блоки с координатами. Для каждого видно `y0`, `y1` и начало текста:

- колонтитул: `y1` меньше 50 - верхнее поле
- заголовок и абзац: середина страницы
- подвал: `y0` больше 792 (высота 842 минус 50) - нижнее поле

Покажите, что по координатам шапка и подвал отделяются без регулярных выражений по тексту.

Для сравнения запустите скан:

```bash
PYTHONPATH=. uv run python src/main/03_page_text.py 5
```

Ожидаемо: пустой текст и ни одного блока. PyMuPDF не распознает картинку сам, для таких страниц нужен OCR или vision-модель.

## 4. Убрать колонтитулы и номера страниц

Время: 8 минут.

Откройте `src/lib/pdf_utils.py` и разберите правило из двух условий:

- `is_in_margin` - блок целиком лежит в верхнем или нижнем поле `MARGIN_PT = 50` пунктов
- `find_repeated_margin_texts` - текст блока после `normalize_text` повторяется хотя бы на `REPEAT_SHARE = 60%` страниц

`normalize_text` из `src/utils/text.py` заменяет цифры на `#`. Поэтому «Страница 1 из 5» и «Страница 3 из 5» превращаются в одну строку «Страница # из # - редакция #» и считаются повтором.

Запустите сравнение:

```bash
PYTHONPATH=. uv run python src/main/04_clean_pages.py 3
```

Ожидаемо:

- в списке повторяющихся текстов две строки: «Орбита - руководство покупателя» и «Страница # из # - редакция #»
- «до очистки» - текст с колонтитулом и подвалом
- «после очистки» - только заголовок «Гарантия и ремонт» и абзац про гарантию

Обсудите, почему нужны оба условия:

- только поле страницы удалит полезную сноску внизу единственной страницы
- только повтор удалит одинаковый заголовок раздела в теле страницы

Если останется минута, поменяйте в `config/variables.py` `MARGIN_PT` на `10` и запустите шаг снова: колонтитул выйдет за поле и вернется в текст. Верните `50`.

## 5. Сохранить страницы в JSONL

Время: 5 минут.

```bash
PYTHONPATH=. uv run python src/main/05_export_jsonl.py
```

Ожидаемо:

```text
page 1:  ... chars | ok
page 2:  ... chars | ok
page 3:  ... chars | ok
page 4:  ... chars | ok
page 5:    0 chars | needs_ocr
saved 5 pages to pages.jsonl
```

Откройте `data/pages.jsonl`. В каждой строке:

- `file` - `orbita_manual.pdf`
- `page` - номер страницы с единицы, как видит человек
- `text` - очищенный текст без колонтитулов
- `chars` - длина текста
- `needs_ocr` - `true` только у страницы 5

Подчеркните: номер страницы пишется при извлечении. После чанкинга и загрузки в векторную базу его уже не восстановить, а без него ответ нельзя проверить.

## 6. Задать модели вопрос по найденной странице

Время: 7 минут.

Откройте `src/lib/llm_client.py`. Это официальный SDK `openai`: клиент `OpenAI(api_key=...)` и один вызов `chat.completions.create` с `temperature=0`. Системный промпт требует отвечать только по странице и указать источник.

Откройте `src/main/06_ask_page.py`. Поиск страницы здесь намеренно простой: пересечение основ слов вопроса и страницы. Основы считает `stems` в `src/utils/text.py`: первые 5 букв слова снимают русские окончания. Страницы с `needs_ocr` пропускаются. Векторный поиск и чанкинг - следующий шаг, сегодня важно качество входных данных.

Запустите вопрос по умолчанию:

```bash
PYTHONPATH=. uv run python src/main/06_ask_page.py
```

Ожидаемо:

- `skipped scan pages: [5]`
- `best page: orbita_manual.pdf, стр. 3`
- текст страницы без колонтитулов
- ответ модели: гарантия 6 месяцев, сервисный центр на улице Лесной, дом 12, или курьер, со ссылкой `(orbita_manual.pdf, стр. 3)`

Теперь спросите то, что написано только на скане:

```bash
PYTHONPATH=. uv run python src/main/06_ask_page.py "Какой срок ремонта указан в акте приема?"
```

Ожидаемо: страница 5 пропущена, лучшей окажется страница 3 про ремонт, и модель ответит «нет в документе». Срок 21 день есть только на картинке страницы 5, и в текстовый контур он не попал.

Если запрос падает с `RuntimeError: OPENAI_API_KEY не задан`, проверьте `.env`. Ошибка `401` - неверный ключ, `404 model not found` - поменяйте `OPENAI_MODEL` на доступную вашему аккаунту модель.

Вывод занятия:

- PDF - холст, текст и порядок чтения восстанавливает библиотека
- колонтитулы убираются по координатам и повтору, а не вручную
- страница с номером - минимальная единица источника для RAG
- скан без OCR - пробел в базе знаний, его нужно пометить, а не пропускать незаметно

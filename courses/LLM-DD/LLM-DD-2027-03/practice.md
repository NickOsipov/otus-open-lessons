# Практика: OCR страниц PDF для базы знаний

Соберем учебный PDF интернет-магазина из четырех текстовых страниц и одного скана. Найдем страницу без текстового слоя, распознаем ее через vision-модель OpenAI, сохраним страницы с пометкой источника текста и зададим модели вопрос по распознанной странице. План совпадает со слайдом «Практика» в `presentation.md`.

Все команды выполняются из `courses/LLM-DD/LLM-DD-2027-03/code/`. Настройки лежат в `config/variables.py`, предметная логика в `src/lib/`, шаги практики в `src/main/`, мелкие помощники в `src/utils/`. Скрипты запускаются с `PYTHONPATH=.`, чтобы импорты `config` и `src` находились от корня `code/`.

## Что понадобится

- установленный `uv`
- Python 3.12.8, который `uv` может установить автоматически
- ключ OpenAI API (`OPENAI_API_KEY`) с доступом к модели с поддержкой картинок, по умолчанию `gpt-4o-mini`
- доступ в интернет до `api.openai.com` (нужен на шагах 4 и 6)

Бэкенд практики - OpenAI API. Вызовы идут через официальный SDK `openai`, ручных HTTP-запросов нет. Шаги 1-3 и 5 работают локально. Шаги 4 и 6 обращаются к API.

Спикеру до вебинара:

1. Выполнить `uv sync` и заполнить `.env`, проверить ключ.
2. Прогнать все шаги подряд и убедиться, что вывод совпадает с ожидаемым.
3. Сохранить копию `data/ocr/page_5.txt` как запасной план. Если API недоступен, вернуть файл в `data/ocr/`: шаг 4 пропустит вызов из-за кэша, шаг 6 покажет найденную страницу, но ответ модели без API не получится.

## 1. Собрать учебный PDF и настроить окружение

Время: 5 минут.

Перейдите в папку демо, установите зависимости и скопируйте настройки:

```bash
cd courses/LLM-DD/LLM-DD-2027-03/code
uv sync
cp .env.example .env
```

Впишите в `.env` свой ключ. Модель можно поменять, не трогая код:

```dotenv
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini
```

Ключ живет только в `.env`, файл не попадает в git. Не показывайте ключ на экране при демонстрации.

Соберите учебный PDF:

```bash
PYTHONPATH=. uv run python src/main/01_make_pdf.py
```

Ожидаемо: `saved shop_manual.pdf: 5 pages`. Файл появится в `data/shop_manual.pdf`.

Откройте PDF в любом просмотрщике и покажите слушателям:

- страницы 1-4: текст с серым колонтитулом «Интернет-магазин - руководство покупателя» сверху и подвалом «Страница N из 5 - редакция 2026» снизу
- страница 5 «Акт приема устройства» выглядит так же, но текст на ней не выделяется мышью: это картинка

Коротко объясните, как сделана страница 5 в `src/lib/demo_pdf.py`: функция `make_scan_image` рисует страницу, превращает ее в PNG через `get_pixmap`, и в итоговый PDF вставляется только эта картинка. Так выглядит любой отсканированный акт или договор.

## 2. Осмотреть PDF: текстовый слой и сканы

Время: 5 минут.

```bash
PYTHONPATH=. uv run python src/main/02_inspect_pdf.py
```

Ожидаемо: заголовок документа и таблица по страницам:

- страницы 1-4: сотни символов, `0` картинок, вердикт `текст`
- страница 5: `0 chars`, `1 img`, вердикт `скан, нужен OCR`

Разберите в коде `has_text_layer` из `src/lib/pdf_utils.py`: страница считается текстовой, если в текстовом слое не меньше `MIN_TEXT_CHARS` символов. Порог - эвристика, на реальных документах его подбирают.

Вывод: на скане `get_text()` возвращает пустоту. Без проверки такая страница молча попадет в базу знаний пустой записью.

## 3. Отрисовать страницы-сканы в PNG

Время: 5 минут.

```bash
PYTHONPATH=. uv run python src/main/03_render_scan.py
```

Ожидаемо:

```text
saved page_5.png
rendered 1 scan page(s)
```

Файл лежит в `data/ocr/page_5.png`. Откройте его и покажите, что серийный номер и срок читаются глазами.

Разберите `render_page_png` в `src/lib/pdf_utils.py` и `RENDER_DPI = 150` в `config/variables.py`. Качество картинки - первый рычаг качества OCR: мелкий или размытый текст дает ошибки в цифрах и похожих буквах.

## 4. Распознать скан через vision-модель и проверить поля

Время: 10 минут.

Откройте `src/lib/llm_client.py`. Это тот же OpenAI SDK, что и в текстовых уроках. Отличие в сообщении: вместо строки передается список из текста с промптом и картинки в формате `{"type": "image_url", "image_url": {"url": "data:image/png;base64,..."}}`. `OCR_PROMPT` просит переписать текст как есть и не пересказывать, `temperature=0` убирает случайность.

```bash
PYTHONPATH=. uv run python src/main/04_ocr_scan.py
```

Ожидаемо:

- строка `page_5.txt: N chars, совпадение с эталоном демо: X%`
- строка `ключевые поля не найдены: нет`, если серийный номер `SN-7781-204` распознан
- распознанный текст между строками `--- OCR text ---`

Значения N и X зависят от модели и запуска. Если X заметно ниже, сверьте текст из блока `--- OCR text ---` с картинкой `data/ocr/page_5.png` и покажите зрителям конкретные ошибки.

Разберите две функции:

- `similarity` в `src/utils/text.py` считает долю совпадения текстов: 100% - полное совпадение. Эталон известен только в демо, поэтому эта метрика работает здесь, а в реальном проекте эталона нет.
- `check_key_fields` в `src/main/04_ocr_scan.py` проверяет, что в тексте есть ключевые поля из `SCAN_KEY_FIELDS`. В реальной работе это серийные номера, суммы, даты. Проверка грубая, но ловит пропуски сразу.

Повторный запуск покажет кэш:

```bash
PYTHONPATH=. uv run python src/main/04_ocr_scan.py
```

Ожидаемо: `page_5.txt: уже распознано, вызов API не делаем`. Чтобы распознать заново, удалите `data/ocr/page_5.txt`.

## 5. Собрать страницы с источником текста

Время: 5 минут.

```bash
PYTHONPATH=. uv run python src/main/05_export_jsonl.py
```

Ожидаемо:

```text
page 1: ... chars | text_layer
page 2: ... chars | text_layer
page 3: ... chars | text_layer
page 4: ... chars | text_layer
page 5: ... chars | ocr
saved 5 pages to pages.jsonl
```

Откройте `data/pages.jsonl`. В каждой строке:

- `file` - `shop_manual.pdf`
- `page` - номер страницы с единицы, как видит человек
- `text` - текст страницы
- `chars` - длина текста
- `source` - откуда текст: `text_layer` из PDF, `ocr` из распознавания, `missing` если текста нет совсем
- `needs_ocr` - `true` только при `missing`

Подчеркните: номер страницы и источник пишутся при извлечении. Если пометки `ocr` нет, ответ по странице 5 нельзя отличить от ответа по обычному тексту, и проверить его нечем.

## 6. Задать вопрос по распознанной странице

Время: 7 минут.

Откройте `src/main/06_ask_page.py`. Поиск страницы простой: пересечение основ слов вопроса и страницы, как в предыдущих уроках серии. Страницы без текста пропускаются, а страница из OCR участвует наравне с текстовым слоем.

Запустите вопрос по умолчанию:

```bash
PYTHONPATH=. uv run python src/main/06_ask_page.py
```

Ожидаемо:

- `pages without text: []`: после OCR пустых страниц нет
- `best page: shop_manual.pdf, стр. 5, source: ocr`
- текст страницы 5 с серийным номером `SN-7781-204`
- ответ модели со ссылкой `(shop_manual.pdf, стр. 5)`: срок ремонта не более 21 рабочего дня

Проверьте случай, когда ответа в документе нет:

```bash
PYTHONPATH=. uv run python src/main/06_ask_page.py "Можно ли оплатить ремонт в рассрочку?"
```

Ожидаемо: модель отвечает `нет в документе`. Она не должна придумать условия рассрочки.

Если запрос падает с `RuntimeError: OPENAI_API_KEY не задан`, проверьте `.env`. Ошибка `401` - неверный ключ. Ошибка `404 model not found` или отказ по поводу изображений - поменяйте `OPENAI_MODEL` на модель с поддержкой картинок, доступную вашему аккаунту.

Вывод занятия:

- страница без текстового слоя не пустая, а нераспознанная: ее надо распознать и проверить
- vision-модель читает скан через тот же SDK, что и текст, но ее ответ проверяют по ключевым полям
- источник текста (`text_layer` или `ocr`) записываем вместе с номером страницы, чтобы ответ можно было проверить
